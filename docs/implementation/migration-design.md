# 多轮迁移与优化设计

适用于历史共享目录或本地归档：首次迁入大部分，随后按需增补和修正。本文定义待抽取的通用能力，不表示 Toolkit CLI 或目标实例已支持这些行为。

## 模式与比较依据

| 模式 | 比较与执行 | 不做什么 |
| --- | --- | --- |
| 首轮主体导入 | 必要枚举时保存路径、类型、大小、源 mtime；空目标且迁移独占时减少无意义目标查询 | 不丢弃源时间，不把非空目标当空库追加 |
| 只新增 | 根据已确认清单和本次发现范围选择新增项 | 不覆盖同名目标，不推导删除 |
| 更新变化 | 比较上次成功导入的源版本，保护预期旧目标版本 | 不拿上传时间代替源版本，不覆盖外部修改 |
| 定向修错 | 仅处理指定失败或解封范围 | 不每轮重新探测全部已知错误 |
| 时间修正 | 使用原始源时间，仅更新已确认对应对象的元数据 | 不因目标时间错误重传内容，不默认内容哈希 |

发现状态与成功应用状态分开保存。源清单已更新不代表内容已写入目标；源缺失也可能是扫描不完整、权限失败或暂时离线，删除和重命名默认只形成候选清单。

目录 mtime、文件数或相同大小不能证明整个子树未变化。没有可靠变更日志的 SMB 仍需要必要的元数据枚举；定向增补必须写明未覆盖范围。

## 稳定输入与跨轮恢复

上传读取稳定输入，复制任务不得同时修改正在上传的基线。可按实际存储能力选择快照、独立 inode 的 reflink 或已预算副本；硬链接不提供内容隔离，未完成的 partial 不进入上传范围。

使用单个任务账本保存目标 UUID、配置指纹、输入版本、路径与源属性、操作、预期目标版本、回执和错误。字段是设计语义，不要求服务端新增任务表或再建一套平台。源版本缺少原时间时标记未知，不能用后补采的当前值伪造历史记录。

恢复从持久 pending 集合领取任务，不从整库重新生成所有工作。跨轮保留旧未完成项，但新版本优先；旧待处理项不能覆盖后续已成功修正的内容。目标版本条件不可用时，覆盖更新须在目标业务禁写且迁移写入者唯一的窗口执行，否则保留冲突。

客户端批次编号不等于服务端幂等键。请求超时或响应丢失后，先核对该批次目标版本和结果；证据不足保留 unknown，不能立即整批重发或二分重传。

已知单项错误单独留账并隔离，普通增补跳过，明确修复时再检查指定项。身份失效、网络或磁盘系统性故障暂停相关写入，不能归为可忽略的文件错误。现有执行器未实现隔离或跨轮恢复时，先适配验证，不修改旧指纹或清空状态强行续跑。

## 原生合批与时间保留

按父目录与动作分组，新增和覆盖更新分开；使用文件数与字节双上限、有限在途和全局提交节奏。批次优先减少请求与原生提交次数，数据块处理仍有逐文件成本。并发、批次大小和大文件分片以实际服务压力测试选择，不预置万能参数。

源文件与目录 mtime 分别保存，记录原精度、时区语义和目标精度。目录在相关子项完成后按受影响范围自底向上修正，包含空目录；不能用目录创建时间、子文件最大时间或库提交时间代替源目录时间。

已核对的 [Server 上传路径](https://github.com/eaopen/cloudfile-server/blob/a01f523e2287069272ed32f4a6affc51e2e74fe3/server/upload-file.c) 将 `last_modify` 解析为一个 mtime，传入多文件提交。因此该路径可表达批次共用时间，不能据此承诺每项不同时间都被保留。其他上传路径和实际部署仍需分别验证。

优先评估原生逐项批量时间或独立元数据修正接口。目标暂不支持时保存源时间和 time_pending，内容与时间修正分开推进，不默认退回海量单文件提交。不得将请求 ACK 写成“时间已完整保留”或承诺原生不支持的创建时间。

## 核对等级与完成边界

独立核对默认只读、按变化/修复/unknown 及受影响目录增量执行；不要求每轮增补前全库核对。

| 证据等级 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 上传响应 | 对应批次响应中可确认的名称、大小和结果 | 所有文件内容一致或源时间正确 |
| 元数据核对 | 覆盖范围内路径、类型、大小、文件/目录 mtime 的匹配与差异 | 大小与时间相同的文件必然内容相同 |
| 显式内容核验 | 所选范围的抽样或完整内容比较结果 | 未覆盖文件也已核验 |

默认不触发独立内容哈希，元数据不足就保留未知；用户选择内容核验时说明范围、源观察条件、目标版本与额外读取成本。执行器自身必要的传输校验与独立全内容核验是不同成本。

每轮报告本轮成功、失败、跳过、隔离、unknown、时间待修和未覆盖项。进度查询复用汇总，不全量遍历明细；上传完成、时间修正、索引、授权与业务验收分别报告。最终停写、开放、回切或结束迁移由业务安排和明确授权决定，工具不自动切换。

## 大库与优化评价

近千万是文件和目录合计的设计目标，尚未作为 Toolkit 已支持规模。采用落盘路径/parent 与状态索引、键集分页、有界缓存、增量计数及流式报告；不能将整目录返回伪装成真实分页，也不能静默截断。

分别选择普通目录、海量小目录、超大扁平目录、深层目录和大文件样本，逐级扩大。记录文件率、目录率、字节率、源请求及读取量、目标请求与提交、账本事务、内存、耗时和业务延迟。元数据压测不等于真实 SMB 和 CloudFile 吞吐验证。

同一限额和样本下比较完整流程，包含恢复、时间修正与核对成本。断点复用可能仍需读取源和 partial，只有实测才能说明是否减少重传或源读取；更高并发、更大批次和账本分片不作为无条件优化。

# 部署实施与历史导入

解决问题：准备部署与可靠导入历史文件。需要源目录读取权限、目标范围写入权限，以及适用的实施授权。

安装、升级、Compose 与离线工具以 [cloudfile-docker](https://github.com/eaopen/cloudfile-docker) 对应版本说明为准。

进一步阅读：[多轮迁移与优化设计](migration-design.md) · [现有工具与收敛边界](tools.md) · [近期交付计划](../delivery-plan.md)

## 导入流程

1. 确认源范围、目标资料库 UUID 和路径、业务规则、覆盖策略与授权；保持源相对目录结构。显示名、业务键和物理存储位置不能混用。
2. 检查容量、连接和小范围真实读写；制定可审阅计划，包含新增、更新、例外、批次与恢复策略。
3. 首轮复用枚举取得的源时间、大小等属性，保存源版本依据；优先同目录原生合批与持久化文件级状态。不要为每个文件调用 Agent。
4. 增量按业务选择只新增、更新变化或定向修错，比较上次成功导入的源版本。目标时间异常不等于内容变化；时间保留未核实则记录待修。
5. 结果未知先核对原任务和目标结果，恢复仅处理未确认或变化项。报告成功、失败、跳过和待确认数量及错误例外。
6. 每轮按需增补和核对，不强制先做全库哈希。最终开放前按业务约定完成停写、差量补齐、选定等级的完整性检查、索引、权限和代表用户验收；结束与开放由业务安排决定。

正常结果：有持久状态、错误清单、源版本依据与验收证据；主体上传成功不等于迁移完成。历史错误需解决或形成明确业务例外。

## 现有工具与后续收敛

[cloudfile-docker/tools/migrate](https://github.com/eaopen/cloudfile-docker/tree/dev/tools/migrate) 是现有工具入口。使用前阅读该版本 README 和实际帮助，检查目标兼容性；不能把旧业务键导入方式直接用于 UUID 绑定存储。

通用批量实现计划见 [CLI 规划](../cli.md)。当前不移动正在运行的工具、不复制客户配置、不宣称已实现 Toolkit 导入命令。底层实例恢复继续留在 Docker 仓库。

# CLI 范围与交付计划

**本仓库尚无可安装或运行的 `cloudfile` CLI。以下均为规划，不是命令使用说明。**

| 规划能力 | 用途 | 接入条件 |
| --- | --- | --- |
| `cloudfile import` | 计划、执行、恢复、状态、报告 | 抽取经验证的通用批量机制，完成目标兼容与恢复验证 |
| `cloudfile doctor` | 连接、认证、版本、核心能力诊断 | 真实只读接口与明确能力检查 |
| `cloudfile ls` / `get` | 有权目录列表与下载 | 当前身份、分页与输出限制 |
| `cloudfile status` | 库、任务、服务摘要 | 已有汇总，不遍历所有明细 |
| `cloudfile search` | 权限内检索 | 当前实例搜索能力真实可用 |
| `cloudfile access explain` | 有效权限与拒绝原因 | 服务端提供可信解释，不另造权限逻辑 |

后续有真实需求再增加受控上传，不预置删除、权限管理或数据库修复命令。当前工具入口见 [实施手册](implementation/README.md)。

## 实现约束

- 人类可读输出与稳定 `--json` 使用同一实现，明确退出码、错误分类、分页和输出上限。
- Profile 仅保存实例地址等非敏感配置；认证复用服务端支持机制，凭据不入库、不写日志。
- 普通 HTTP 操作独立于 Docker 和完整源码环境；缺失能力明确报告不支持。
- 导入状态由执行器持久保存，Skill 不持有队列；结果未知先查询原任务，避免重复写入。
- 兼容性以实际服务版本与能力为准；每项命令需可执行示例和相应验证后才能标记已交付。

首批验收场景：普通用户找资料、实施人员增量导入、支持人员定位访问异常。首次通用导入交付需核对合批、源版本保存、错误隔离、中断恢复与完整性证据。

# 近期交付计划

以实用任务为单位交付，当前仅有角色手册、企业集成范例和三个工作流 Skills；CLI、通用导入引擎与独立核对工具尚未交付。不承诺日期或未测量的规模、性能。

| 顺序 | 最小交付 | 完成依据 |
| --- | --- | --- |
| 1. 能力盘点 | 对照 [工具索引](implementation/tools.md)，确定原执行器、许可、客户依赖、目标绑定和抽取边界 | 明确哪些机制可复用、哪些尚缺；不改正在运行任务 |
| 2. 导入纵向闭环 | 稳定输入、固定 UUID、范围计划、同目录合批、持久回执、状态与报告 | 小范围真实导入，单项错误隔离、未知结果核对与原任务恢复通过 |
| 3. 多轮增补 | 只新增、变化更新、定向修复及旧 pending 的版本顺序 | 新增、同名冲突、源变化、旧任务不覆盖新内容、目标外部修改保护通过 |
| 4. 时间与独立核对 | 原始文件/目录时间记录、time_pending、只读增量核对 | 区分元数据匹配与内容证明；无批量时间接口明确报告缺口；不阻塞无关增补 |
| 5. 查询、诊断与 Skills 验收 | 最小 doctor/ls/get/status，按服务端能力增加 search/access explain | 有权读取、无权拒绝、能力缺失、分页上限及三个真实任务场景通过 |

时间能力的技术验证应在第 1 步启动，避免导入设计依赖不存在的契约；批量修正实现可独立推进。企业集成指南持续跟随组件契约维护，不要求先实现完整 CLI 才能接入业务应用。

## 首个实现的范围

只做一个执行实现和简单本地持久账本；Agent 调度任务级动作，人类与 Agent 共用执行结果。先明确错误分类、退出码、受限 JSON 输出、配置与凭据来源，不预先建设调度平台、MCP 服务或完整 API SDK。

首个小范围验收覆盖空目录、不同文件时间、同名目标、单项拒绝访问、源处理中变化、响应丢失和中断恢复。通过后按目录分布逐级扩大；规模账本测试、真实传输、服务负载与业务验收分开记录。

每次交付同步更新 [CLI 状态](cli.md)、对应角色手册与 Skill。只有实现存在、帮助和示例可运行、受影响行为完成验证后，才将某项能力改为“已交付”。

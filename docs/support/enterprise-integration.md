# 企业文件管理集成范例

面向开发与技术支持：将 CloudFile 接入企业门户、项目管理或业务应用，为员工提供统一文件入口。本例使用虚构的“项目资料”场景，不包含特定客户的系统、配置或数据。

本文是接入指南，不是完整 API 契约或可执行示例。接口、认证方式、组件能力和部署状态须以目标版本核实；本仓库 CLI 尚未实现。

## 场景与职责

员工从企业门户进入“项目资料”，查看自己有权访问的目录，上传交付文件、预览资料，按需通过本地应用编辑。项目负责人在选定的权限管理入口配置访问规则，支持人员能追踪失败发生在哪个环节。

| 系统或组件 | 负责什么 |
| --- | --- |
| 企业应用 | 项目、流程、业务对象、页面入口与业务关联 |
| 身份提供方 | 验证登录身份；门户会话不能直接替代 CloudFile 登录证明 |
| 企业组织目录（可选） | 提供受信用户、组织、角色和成员事实；目录事实本身不授予文件权限 |
| CloudFile | 文件、目录、版本、有效权限与文件访问执行 |
| 前端组件或适配层 | 在支持的认证方式下调用接口，展示结果和错误；不另算文件权限 |
| 预览、本地 Agent 与浏览器扩展（可选） | 承接当前版本支持的预览或本地打开、编辑流程 |

独立部署可直接使用 CloudFile 账号与权限管理，不要求接入企业组织目录。通用产品不依赖某个业务系统。

## 身份、组织与权限

### 登录身份

接入前确定受信身份源、稳定用户 UID 和 CloudFile 原生账号的关联规则。不要用邮箱、姓名或可复用员工编号自动合并账号；已有文件归属不能随显示属性变化而迁移。

OIDC 的 issuer + subject 是认证主体标识，不能直接与业务 UID 混为一谈，也不能跨 issuer 只比较 subject。是否支持指定登录方式、首次建号或目录关联，以目标版本身份契约为准。

前端使用服务端支持的会话或用户授权机制。机器凭据只用于约定的服务端调用，不交给浏览器；不能让所有员工共用管理员令牌访问文件。

### 组织和角色

如需接入目录，显式约定用户、组织、角色的稳定标识、命名空间、启停用状态与成员来源。相同显示名不等于同一主体，父组织信息不自动意味着继承其成员或文件权限。

区分组织实体同步、用户成员同步和文件授权三个步骤。登录成功或同步到角色名称，不能证明该用户已获得目标目录权限。同步频率、缓存 TTL、禁用和撤权生效时间应纳入验收。

### 权限配置入口

CloudFile 原生管理是默认方式；已有业务权限管理的企业应用，可在目标版本支持时将期望规则发布到同一权限执行层。两种方式不建立两套独立的有效权限计算。

每个资料库约定一个日常配置责任方。必须分工时，明确互不重叠的规则范围；切换责任方前暂停旧发布者、核对现状再交接。版本检查只能检测过期提交，不能声称已技术性隔离所有交替写入。

业务页面隐藏按钮只改善界面体验，服务端仍须按当前身份检查列表、读取、下载、写入与提交权限。

## 业务页面与文件操作

| 接入任务 | 实用做法 | 应验证什么 |
| --- | --- | --- |
| 业务对象关联 | 企业应用保存项目标识与资料库 UUID、目录路径的关联；路径变化需维护引用 | 同名项目不串库，目录改名或移动后能定位或明确报失效 |
| 文件组件嵌入 | 按选定版本的组件接入方式配置地址、登录与目标范围 | 登录跳转、会话、跨域或代理路径正确；传入路径不扩大权限 |
| 列表与搜索 | 列表分页；仅在实例启用且可用时接入搜索 | 无权对象不泄露，未启用搜索有明确提示 |
| 上传与替换 | 明确目标目录、同名策略和传输状态，按实际接口使用直传或分片 | 取消、中断、重复请求和提交后结果可核实 |
| 下载与打包 | 按当前身份获取文件；多文件打包使用版本支持的服务端流程 | 文件名、目录结构、错误响应和过期链接处理正确 |
| 预览与本地编辑 | 按需接入对应组件；区分预览、只读打开、编辑和写回 | 原文件版本与写回结果可核实，缺少组件时有可理解的提示 |

业务标识、资料库显示名、资料库 UUID 和物理存储目录是不同概念。不能假设业务标识可以指定物理目录；文件应通过公开文件接口访问，不让业务服务直接修改存储文件。

若使用 iframe，先核对目标版本是否支持该嵌入方式及会话策略；若使用前端组件，按其契约集成。不要为绕过登录、跨域或下载限制而关闭身份校验或把管理员凭据放入 URL。

本地编辑能力需单独核对 Agent、扩展、宿主系统和服务端版本。看到文件成功打开，不等于保存已写回，也不等于冲突、断网恢复或独占编辑已经通过。

## 最小接入与验收

1. 选定实际部署版本，记录所需接口、可选组件、认证方式和缺失能力。使用隔离测试库与虚构资料，不接入真实生产文件作为初次试验。
2. 创建一个“项目资料”关联，使用测试用户完成门户登录、进入目录、列出与读取文件；另用无权用户验证拒绝访问。
3. 加入授权的上传或替换，读取目标内容和版本确认结果；断连或超时后先查原操作结果，不能直接重放写入。
4. 按需要验证组织成员变化、禁用与撤权、授权发布版本冲突、搜索或预览不可用、文件移动和本地编辑失败。撤权按约定 TTL 和会话规则检查，不承诺即时生效。
5. 交付组件版本、脱敏配置说明、业务关联规则、权限责任方、场景结果及未解决项。接口测试、构建、部署和真实用户验收分别记录。

正常结果：有权用户能在业务入口完成目标操作，无权用户无法通过直接调用接口绕过限制；支持人员能区分认证、授权、传输与提交故障。失败时携带脱敏的环境、时间、动作及错误进入 [排查流程](README.md#排查流程)。

## 开发者与 Agent 分工

Agent 适合阅读契约、整理字段映射、编写适配代码、生成虚构样例、在授权测试环境验证有限场景，以及分析脱敏错误。开发任务授权不自动包含发布生产配置、全局授权或真实文件批量变更。

文件操作复用 [cloudfile-files](../../skills/cloudfile-files/SKILL.md)，排查复用 [cloudfile-diagnose](../../skills/cloudfile-diagnose/SKILL.md)。本指南不新增一套集成执行器或万能管理员工具。

## 契约与代码归属

详细字段与路由以对应组件版本为准，接入项目应记录所依据的版本或提交，不把浮动开发分支文档当作已部署能力。

- [Hub API](https://github.com/eaopen/cloudfile-hub/blob/dev/docs/API.md)、[企业目录事实契约](https://github.com/eaopen/cloudfile-hub/blob/dev/docs/ENTERPRISE-DIRECTORY-CONTRACT.md)：接口与目录适配边界。
- [身份关联规则](https://github.com/eaopen/cloudfile-hub/blob/dev/docs/SSO-IDENTITY-RULES.md)、[权限配置责任约定](https://github.com/eaopen/cloudfile-hub/blob/dev/docs/ACL-CONFIG-WRITER-OWNERSHIP.md)：身份及授权发布边界。
- [CloudFile Server](https://github.com/eaopen/cloudfile-server)：文件传输与存储执行实现；[CloudFile Docker](https://github.com/eaopen/cloudfile-docker)：部署配置、组件启用与升级。

通用接入指南和可复用工具留在 Toolkit，API 契约与实现随组件维护；企业应用自己的页面、组织查询、业务字段映射、实例配置及交付证据留在其项目中。
